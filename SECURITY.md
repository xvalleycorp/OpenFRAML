# Security policy

## Reporting a vulnerability

Do not report vulnerabilities in public issues, discussions or pull requests.

Report privately through GitHub:
[Report a vulnerability](https://github.com/xvalleycorp/OpenFRAML/security/advisories/new).
Include the affected module and version, how to reproduce it, and the impact you expect.

A fraud system is itself a target: whoever learns how the rules decide learns how to avoid them. Weaknesses that let
a payment bypass the gate, or reveal a bank's rules or thresholds, are vulnerabilities too.

## Our commitments

| Step | Within |
| --- | --- |
| Acknowledge the report | 3 working days |
| Assess severity and reply with a plan | 10 working days |
| Release a fix for a critical vulnerability | 30 days, or as agreed for disclosure |

Once a fix is out, the project publishes a GitHub Security Advisory, with a CVE where appropriate, and credits the
reporter if they wish. Vulnerabilities in RuleStone are reported to RuleStone under its own `SECURITY.md`.

## Supported versions

The project is before 1.0: only the latest `main` receives security fixes.
